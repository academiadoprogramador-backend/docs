No documento anterior, aprendemos a converter objetos para JSON usando `System.Text.Json`.

Agora vamos dar o próximo passo.

Vamos aprender a salvar esse JSON em um arquivo no disco e carregá-lo de volta quando o programa iniciar.

Esse processo de manter dados entre execuções se chama **persistência**.

---

## O problema de manter dados só na memória

Quando usamos apenas listas em memória, os dados existem apenas enquanto o programa está aberto.

```csharp
List<Categoria> categorias = new List<Categoria>();
```

Assim que fechamos o terminal, tudo desaparece.

Para resolver isso, precisamos escrever os dados em algum lugar que continue existindo depois que o programa encerrar.

Esse lugar é o **disco**.

---

## Salvando dados em arquivo

O .NET oferece a classe `File` para trabalhar com arquivos.

Para salvar um texto em arquivo, usamos `File.WriteAllText`:

```csharp
string conteudo = "Ola, arquivo!";
File.WriteAllText("meu-arquivo.txt", conteudo);
```

Esse metodo recebe dois parametros:

- o caminho do arquivo;
- o conteudo a ser escrito.

Se o arquivo nao existir, ele e criado.

Se o arquivo ja existir, ele e substituido.

---

## Lendo dados de arquivo

Para ler um arquivo, usamos `File.ReadAllText`:

```csharp
string conteudo = File.ReadAllText("meu-arquivo.txt");
Console.WriteLine(conteudo);
```

Esse metodo le todo o conteudo do arquivo e retorna como string.

---

## Combinando serializacao com arquivo

Agora vem a parte interessante.

Podemos unir os dois conceitos:

1. serializar um objeto para JSON;
2. salvar esse JSON em um arquivo.

```csharp
Categoria categoria = new Categoria();
categoria.Id = 1;
categoria.Nome = "Padaria";

JsonSerializerOptions options = new JsonSerializerOptions();
options.WriteIndented = true;

string jsonString = JsonSerializer.Serialize(categoria, options);

File.WriteAllText("categoria.json", jsonString);
```

Executando esse codigo, um arquivo `categoria.json` sera criado no disco com o conteudo:

```json
{
  "Id": 1,
  "Nome": "Padaria"
}
```

---

## Carregando dados de arquivo

Para recuperar os dados, fazemos o caminho inverso:

1. ler o JSON do arquivo;
2. desserializar de volta para objeto.

```csharp
string jsonString = File.ReadAllText("categoria.json");

Categoria? categoria = JsonSerializer.Deserialize<Categoria>(jsonString);

Console.WriteLine(categoria?.Nome);
```

Agora o objeto `categoria` contem os mesmos dados que foram salvos.

---

## Verificando se o arquivo existe

Antes de tentar ler um arquivo, e importante verificar se ele existe.

Usamos `File.Exists` para isso:

```csharp
if (File.Exists("categoria.json"))
{
    string jsonString = File.ReadAllText("categoria.json");
    Categoria? categoria = JsonSerializer.Deserialize<Categoria>(jsonString);
}
else
{
    Console.WriteLine("Arquivo nao encontrado. Primeira execucao.");
}
```

Isso evita erros na primeira vez que o programa roda, quando o arquivo ainda nao foi criado.

## O ContextoJson no projeto

No projeto da lista de compras, foi criada uma classe especifica para gerenciar toda a persistencia.

Ela se chama `ContextoJson` e esta na pasta `Compartilhado/Arquivos`.

```csharp
public class ContextoJson
{
    public List<Categoria> Categorias { get; set; } = new List<Categoria>();
    public List<Produto> Produtos { get; set; } = new List<Produto>();
    public List<ListaCompras> ListasDeCompras { get; set; } = new List<ListaCompras>();
}
```

Essa classe:

- centraliza todos os dados que serao salvos;
- define onde o arquivo sera guardado;
- fornece os metodos `Salvar` e `Carregar`.

---

## Definindo o local do arquivo

O caminho do arquivo e definido no construtor da classe:

```csharp
private readonly string caminhoArquivoDados;

public ContextoJson()
{
    string caminhoAppData = Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData);

    string caminhoDiretorioAplicativo = Path.Join(caminhoAppData, "ListaDeCompras");

    Directory.CreateDirectory(caminhoDiretorioAplicativo);

    caminhoArquivoDados = Path.Join(caminhoDiretorioAplicativo, "dados.json");
}
```

Vamos entender cada parte.

`Environment.GetFolderPath` retorna o caminho de pastas especiais do sistema operacional.

`Environment.SpecialFolder.LocalApplicationData` representa a pasta de dados locais da aplicacao.

No Windows, essa pasta fica em:

```text
C:\Users\SeuUsuario\AppData\Local
```

E o local recomendado para salvar dados de aplicacoes, pois:

- nao corre risco de ser excluido acidentalmente pelo usuario;
- cada aplicacao pode criar sua propria subpasta;
- funciona em qualquer versao do Windows.

`Path.Join` une partes de caminhos de forma segura, adicionando as barras corretas automaticamente.

`Directory.CreateDirectory` garante que a pasta exista. Se nao existir, ela e criada.

No final, o arquivo sera salvo em:

```text
C:\Users\SeuUsuario\AppData\Local\ListaDeCompras\dados.json
```

---

## O metodo Salvar

O metodo `Salvar` transforma todos os dados em JSON e escreve no arquivo:

```csharp
public void Salvar()
{
    JsonSerializerOptions options = new JsonSerializerOptions();
    options.WriteIndented = true;
    options.ReferenceHandler = ReferenceHandler.Preserve;

    string jsonString = JsonSerializer.Serialize(this, options);

    File.WriteAllText(caminhoArquivoDados, jsonString);
}
```

Observe que `this` e passado para o serializador.

Isso significa que o proprio `ContextoJson` e serializado por inteiro:

- todas as categorias;
- todos os produtos;
- todas as listas de compras.

Tudo e salvo em um unico arquivo JSON.

---

## O metodo Carregar

O metodo `Carregar` faz o caminho inverso:

```csharp
public void Carregar()
{
    if (!File.Exists(caminhoArquivoDados))
        return;

    string jsonString = File.ReadAllText(caminhoArquivoDados);

    JsonSerializerOptions options = new JsonSerializerOptions();
    options.WriteIndented = true;
    options.ReferenceHandler = ReferenceHandler.Preserve;

    ContextoJson? contextoSalvo =
        JsonSerializer.Deserialize<ContextoJson>(jsonString, options);

    if (contextoSalvo == null)
        return;

    Categorias = contextoSalvo.Categorias;
    Produtos = contextoSalvo.Produtos;
    ListasDeCompras = contextoSalvo.ListasDeCompras;
}
```

Primeiro verificamos se o arquivo existe com `File.Exists`.

Se nao existir, significa que e a primeira execucao. Retornamos sem fazer nada.

Depois lemos o arquivo com `File.ReadAllText`.

Em seguida, desserializamos o JSON de volta para um objeto `ContextoJson`.

Por fim, copiamos os dados carregados para as listas da instancia atual.

Se o arquivo estiver vazio ou corrompido, o `JsonSerializer.Deserialize` retorna `null` e tambem ignoramos.

## Como os repositorios usam o contexto

A classe `RepositorioBase` recebe o `ContextoJson` em seu construtor:

```csharp
public abstract class RepositorioBase<TEntidade> where TEntidade : EntidadeBase
{
    protected readonly ContextoJson contexto;
    protected readonly List<TEntidade> registros;

    protected RepositorioBase(ContextoJson contexto)
    {
        this.contexto = contexto;
        registros = ObterRegistros();
    }

    protected abstract List<TEntidade> ObterRegistros();
}
```

Cada repositorio concreto informa qual lista do contexto deve usar.

Por exemplo, o repositorio de categorias:

```csharp
public class RepositorioCategoria : RepositorioBase<Categoria>
{
    public RepositorioCategoria(ContextoJson contexto) : base(contexto) { }

    protected override List<Categoria> ObterRegistros()
    {
        return contexto.Categorias;
    }
}
```

Agora, quando um registro e cadastrado, editado ou excluido, o repositorio chama `contexto.Salvar()`:

```csharp
public void Cadastrar(TEntidade novoRegistro)
{
    registros.Add(novoRegistro);

    contexto.Salvar();
}
```

Isso garante que qualquer alteracao seja imediatamente persistida no arquivo.

---

## O fluxo completo da persistencia

Agora, quando o programa inicia:

1. O `ContextoJson` e instanciado.
2. O metodo `Carregar` verifica se existe um arquivo salvo.
3. Se existir, os dados sao carregados para as listas.
4. Os repositorios recebem o contexto e acessam as listas correspondentes.

Durante a execucao:

1. O usuario cadastra, edita ou exclui registros.
2. O repositorio altera a lista em memoria.
3. O repositorio chama `contexto.Salvar()`.
4. Os dados sao serializados e salvos no arquivo.

Quando o programa e encerrado e aberto novamente:

1. O `ContextoJson` carrega o arquivo.
2. Os dados voltam exatamente como estavam.

> os dados agora persistem entre execucoes.

---

## Vantagens dessa abordagem

Essa estrutura traz beneficios importantes:

- **separacao de responsabilidades** -- o contexto cuida apenas de salvar e carregar;
- **reutilizacao** -- os repositorios nao precisam saber como a persistencia funciona;
- **centralizacao** -- todas as alteracoes passam por um unico ponto de salvamento;
- **simplicidade** -- nao ha necessidade de banco de dados para persistencia basica.

---

## Limitacoes

E importante entender que essa abordagem tem limitacoes:

- tudo e carregado na memoria de uma vez;
- nao ha consultas otimizadas como em bancos de dados;
- nao ha suporte a concorrencia ou transacoes;
- arquivos grandes podem ficar lentos para salvar e carregar.

Para sistemas pequenos e estudos, essa solucao e suficiente.

Mais adiante, veremos como usar bancos de dados para superar essas limitacoes.

---

## Conclusao

Persistencia em arquivo e a tecnica de manter dados entre execucoes do programa.

Combinando serializacao JSON e arquivos, conseguimos:

- salvar objetos em disco como arquivos JSON;
- carregar esses arquivos na proxima execucao;
- manter os dados organizados em uma classe centralizada.

O `ContextoJson` do projeto da lista de compras e um exemplo pratico dessa abordagem.

Em resumo:

- `File.WriteAllText` salva uma string em arquivo;
- `File.ReadAllText` le uma string de arquivo;
- `File.Exists` verifica se o arquivo existe;
- `Environment.SpecialFolder.LocalApplicationData` define o local apropriado para dados;
- `Directory.CreateDirectory` garante que a pasta exista;
- o `ContextoJson` centraliza a persistencia e se integra aos repositorios.

Com esses conceitos, seus programas podem manter dados entre execucoes, se aproximando cada vez mais de sistemas reais.
