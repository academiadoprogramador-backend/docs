## Docker para Banco de Dados Local

Na aula anterior, organizamos a aplicação em um monólito modular.

Agora vamos preparar um banco de dados local para a aplicação ASP.NET.

Utilizaremos o Docker para executar o SQL Server sem instalar o servidor diretamente no sistema operacional.

O exemplo desta aula utiliza o projeto [`gestao-de-equipamentos-webapp-2026`, versão `v4`](https://github.com/academiadoprogramador-backend/gestao-de-equipamentos-webapp-2026/tree/v4).

Ao final, teremos:

- Docker Desktop instalado;
- Docker CLI funcionando no terminal;
- a imagem do SQL Server baixada;
- um container SQL Server em execução;
- a aplicação configurada para utilizar o SQL Server.

> **Atenção:** a senha apresentada é apenas uma credencial de exemplo para desenvolvimento local. Não utilize esse valor em produção.

## O que é Docker?

Docker é uma ferramenta para executar aplicações dentro de containers.

Um container é uma unidade isolada de execução.

Neste tutorial, o container executará o SQL Server.

Podemos resumir o funcionamento assim:

```text
Imagem
    modelo usado para criar o container

Container
    execução concreta criada a partir da imagem

SQL Server
    serviço executado dentro do container
```

A imagem utilizada será:

```text
mcr.microsoft.com/mssql/server:2022-latest
```

## Docker Desktop e Docker CLI

O **Docker Desktop** é a aplicação que instala e executa o ambiente Docker no computador.

Ele também disponibiliza uma interface gráfica para visualizar containers e logs.

O **Docker CLI** é a interface de linha de comando.

Com ela, podemos:

- baixar imagens;
- criar containers;
- listar containers;
- consultar logs;
- iniciar e parar containers.

Nesta aula, usaremos o Docker Desktop para instalar e iniciar o Docker.

Depois, usaremos a Docker CLI para criar o SQL Server com comandos que podem ser repetidos em qualquer máquina.

## Requisitos

Antes de iniciar, tenha instalado:

- Docker Desktop;
- Git;
- .NET 10 SDK;
- Visual Studio Code ou outro editor de código.

As imagens Linux do SQL Server são destinadas a computadores com arquitetura x86-64, normalmente processadores Intel ou AMD.

Consulte os requisitos atuais na [documentação da Microsoft sobre containers do SQL Server](https://learn.microsoft.com/en-us/sql/linux/install-upgrade/quickstart-install-docker?view=sql-server-ver16).

## Instalando o Docker Desktop

Baixe o instalador na [página oficial do Docker Desktop](https://docs.docker.com/desktop/).

Escolha a versão correspondente ao seu sistema operacional:

- Windows;
- macOS;
- Linux.

### Windows

1. Baixe o instalador para Windows.
2. Execute o instalador.
3. Mantenha a opção de utilizar o WSL 2 quando ela for apresentada.
4. Reinicie o computador se o instalador solicitar.
5. Abra o Docker Desktop.
6. Aguarde até que o Docker esteja em execução.

### macOS

1. Baixe o instalador para a arquitetura do seu computador.
2. Abra o arquivo baixado.
3. Arraste o Docker para a pasta de aplicações, quando solicitado.
4. Abra o Docker Desktop.
5. Autorize os componentes solicitados pelo sistema.
6. Aguarde até que o Docker esteja em execução.

### Linux

No Linux, podemos utilizar o Docker Engine e o Docker CLI seguindo a [documentação oficial de instalação](https://docs.docker.com/engine/install/).

Depois da instalação, inicie o serviço do Docker e execute os comandos de verificação apresentados a seguir.

## Verificando a instalação

Abra o PowerShell, o terminal do sistema ou o terminal integrado do Visual Studio Code.

Execute:

```bash
docker --version
```

Esse comando deve exibir a versão da Docker CLI.

Também podemos executar uma imagem pequena para verificar o funcionamento:

```bash
docker run --rm hello-world
```

O Docker deve baixar uma imagem de teste, criar um container e exibir uma mensagem de sucesso.

O parâmetro `--rm` remove o container de teste depois da execução.

Se o comando falhar, verifique se o Docker Desktop está aberto e se o Engine está em execução.

## Docker Desktop

O Docker Desktop pode ser utilizado para acompanhar o que acontece durante os comandos.

Depois de abrir a aplicação:

1. Acesse a área de containers.
2. Verifique se o Docker está pronto para uso.
3. Depois de criar o SQL Server, localize o container `sqlserver-local`.
4. Abra a área de logs para acompanhar a inicialização.

Também é possível baixar uma imagem pela interface gráfica:

1. Acesse a área de imagens.
2. Escolha a opção para baixar ou fazer pull de uma imagem.
3. Informe `mcr.microsoft.com/mssql/server:2022-latest`.
4. Confirme o download.

O mesmo download pode ser feito pela CLI:

```bash
docker pull mcr.microsoft.com/mssql/server:2022-latest
```

Para listar as imagens baixadas:

```bash
docker image ls
```

## Baixando a imagem do SQL Server

O comando `docker pull` baixa uma imagem de um registro de imagens.

Execute:

```bash
docker pull mcr.microsoft.com/mssql/server:2022-latest
```

O nome da imagem possui três partes:

```text
mcr.microsoft.com
    registro da Microsoft

mssql/server
    imagem do SQL Server

2022-latest
    versão mais recente da linha SQL Server 2022
```

O download pode demorar alguns minutos.

Depois, confira se a imagem está disponível:

```bash
docker image ls
```

O resultado deve apresentar uma imagem com o repositório `mcr.microsoft.com/mssql/server` e a tag `2022-latest`.

## Criando o container SQL Server

O SQL Server precisa receber duas configurações para iniciar:

- aceite da licença;
- senha do usuário administrador `sa`.

Utilizaremos os seguintes valores:

```text
Nome do container
    sqlserver-local

Usuário
    sa

Senha
    Academia@2026!

Porta
    1433
```

A senha precisa seguir a política padrão do SQL Server.

O exemplo possui letras maiúsculas, letras minúsculas, números e símbolos.

Execute no Linux, macOS ou Git Bash:

```bash
docker run \
  --name sqlserver-local \
  --hostname sqlserver-local \
  --env ACCEPT_EULA=Y \
  --env MSSQL_SA_PASSWORD='Academia@2026!' \
  --publish 127.0.0.1:1433:1433 \
  --detach \
  mcr.microsoft.com/mssql/server:2022-latest
```

No PowerShell, execute em uma única linha:

```powershell
docker run --name sqlserver-local --hostname sqlserver-local --env ACCEPT_EULA=Y --env MSSQL_SA_PASSWORD='Academia@2026!' --publish 127.0.0.1:1433:1433 --detach mcr.microsoft.com/mssql/server:2022-latest
```

Os principais parâmetros são:

- `--name`, nome do container;
- `--hostname`, nome do host do SQL Server no container;
- `--env ACCEPT_EULA=Y`, aceite necessário para a imagem iniciar;
- `--env MSSQL_SA_PASSWORD=...`, senha do usuário `sa`;
- `--publish 127.0.0.1:1433:1433`, publica a porta do SQL Server na máquina local;
- `--detach`, executa o container em segundo plano;
- último argumento, imagem utilizada para criar o container.

O nome correto da variável de senha é `MSSQL_SA_PASSWORD`.

`SA_PASSWORD` é uma variável antiga e não deve ser utilizada nos exemplos novos.

## Verificando o container

Para listar os containers em execução:

```bash
docker ps
```

Para listar também os containers que já foram parados:

```bash
docker ps --all
```

O container `sqlserver-local` deve apresentar um status semelhante a `Up`.

O SQL Server ainda pode estar iniciando mesmo quando o container já aparece na lista.

Acompanhe os logs com:

```bash
docker logs --follow sqlserver-local
```

Aguarde uma mensagem semelhante a:

```text
SQL Server is now ready for client connections.
```

Pressione `Ctrl+C` para parar de acompanhar os logs.

Isso não encerra o container.

Também podemos consultar os logs sem acompanhar continuamente:

```bash
docker logs sqlserver-local
```

Se o container estiver com status `Exited`, os logs normalmente indicarão o problema.

Uma causa comum é uma senha que não atende à política do SQL Server.

## Testando o SQL Server

A imagem possui o utilitário `sqlcmd` no caminho `/opt/mssql-tools18/bin/sqlcmd`.

Podemos executá-lo dentro do container:

```bash
docker exec -it sqlserver-local \
  /opt/mssql-tools18/bin/sqlcmd \
  -S localhost \
  -U sa \
  -P 'Academia@2026!' \
  -C \
  -Q "SELECT @@VERSION;"
```

Esse comando executa uma consulta que retorna a versão do SQL Server.

Os parâmetros principais são:

- `docker exec`, executa um comando dentro de um container;
- `-S localhost`, informa o servidor visto de dentro do container;
- `-U sa`, informa o usuário;
- `-P`, informa a senha;
- `-C`, aceita o certificado local;
- `-Q`, executa uma consulta.

Se a versão for exibida, o SQL Server está respondendo.

## Configurando a conexão

O arquivo `GestaoDeEquipamentos.WebApp/appsettings.Development.json` possui uma conexão semelhante a esta:

```json
{
  "ConnectionStrings": {
    "SqlServerDocker": "Server=localhost,1433;Database=GestaoDeEquipamentosDB;User Id=sa;Password=Academia@2026!;TrustServerCertificate=True;MultipleActiveResultSets=True"
  }
}
```

Os dados precisam corresponder ao container criado:

```text
Servidor
    localhost,1433

Banco
    GestaoDeEquipamentosDB

Usuário
    sa

Senha
    Academia@2026!
```

O nome `SqlServerDocker` também é importante.

Na infraestrutura da aplicação, esse nome é utilizado para buscar a string de conexão:

```csharp
string connectionString = configuration.GetConnectionString("SqlServerDocker")
    ?? throw new InvalidOperationException(
        "A string de conexão não foi configurada"
    );
```

Na versão `v4`, o `RepositorioFabricanteEmSql` utiliza essa conexão.

Por isso, as operações de fabricantes são executadas no SQL Server:

- listar;
- cadastrar;
- editar;
- excluir.

Os equipamentos e chamados ainda utilizam arquivos JSON nessa versão da aplicação.

Neste documento, apenas configuramos a conexão.

A criação do banco e das tabelas será apresentada em um documento posterior.

## Comandos básicos do container

Para parar o SQL Server:

```bash
docker stop sqlserver-local
```

Para iniciar novamente:

```bash
docker start sqlserver-local
```

Para reiniciar:

```bash
docker restart sqlserver-local
```

Para remover o container parado:

```bash
docker rm sqlserver-local
```

Depois de remover o container, será necessário executar novamente o comando `docker run` para criar outro.

> **Atenção:** remover o container deste exemplo remove também os dados que estavam dentro dele. Utilize esse comando apenas quando quiser recriar o ambiente local.

## Alterando a porta do host

Se a porta `1433` já estiver sendo utilizada por outro SQL Server, publique outra porta no computador.

Por exemplo:

```bash
docker run \
  --name sqlserver-local \
  --hostname sqlserver-local \
  --env ACCEPT_EULA=Y \
  --env MSSQL_SA_PASSWORD='Academia@2026!' \
  --publish 127.0.0.1:11433:1433 \
  --detach \
  mcr.microsoft.com/mssql/server:2022-latest
```

Nesse caso, altere a string de conexão para:

```text
Server=localhost,11433
```

O primeiro número é a porta do computador.

O segundo número é a porta interna do SQL Server.

## Problemas comuns

### O comando `docker` não foi encontrado

Verifique se o Docker Desktop está instalado e aberto.

No Linux, verifique se o Docker Engine está em execução.

### O container encerrou imediatamente

Consulte os logs:

```bash
docker logs sqlserver-local
```

Verifique se:

- `ACCEPT_EULA=Y` foi informado;
- `MSSQL_SA_PASSWORD` foi informado;
- a senha atende à política do SQL Server;
- há memória disponível para o Docker;
- a arquitetura do computador é compatível.

### A porta 1433 já está em uso

Utilize outra porta no host, como `11433`, e altere a string de conexão da aplicação.

### A aplicação não consegue conectar

Confira:

- se o container possui status `Up`;
- se os logs informam que o SQL Server está pronto;
- se a porta da string de conexão é a mesma publicada pelo Docker;
- se a senha da aplicação é igual à senha do container.

## Checklist

Antes de executar a aplicação, verifique se:

- o Docker Desktop está aberto;
- `docker --version` funciona;
- a imagem `mcr.microsoft.com/mssql/server:2022-latest` foi baixada;
- o container `sqlserver-local` está em execução;
- os logs indicam que o SQL Server está pronto;
- a porta `1433` está publicada;
- a conexão `SqlServerDocker` está configurada;
- a aplicação possui a configuração de conexão esperada.
