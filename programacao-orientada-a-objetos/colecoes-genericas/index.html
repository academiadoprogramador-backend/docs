Coleções Genéricas

Na aula anterior, vimos que Generics permitem criar estruturas que trabalham com tipos diferentes sem perder segurança.

Agora vamos ver um dos usos mais comuns desse recurso no C#:

as coleções genéricas.

Em aplicações reais, quase sempre precisamos trabalhar com vários registros:

  • vários alunos;
  • vários produtos;
  • várias revistas;
  • vários empréstimos;
  • várias contas.

Para isso, o C# oferece coleções prontas no .NET.

Essas coleções usam generics para indicar qual tipo de dado será armazenado.

O problema dos arrays​

Já vimos que arrays permitem guardar vários valores do mesmo tipo:

string[] nomes = new string[3];

nomes[0] = "Ana";
nomes[1] = "Carlos";
nomes[2] = "Marina";

Arrays são úteis, mas possuem uma limitação importante:

o tamanho é definido na criação.

Se criamos um array com 3 posições, ele terá 3 posições.

Não conseguimos simplesmente adicionar um quarto item sem criar outro array.

Em sistemas reais, muitas vezes não sabemos a quantidade de registros com antecedência.

Por exemplo:

  • quantos alunos serão cadastrados?
  • quantos produtos serão adicionados ao pedido?
  • quantas revistas existem no sistema?

Nesses casos, usamos coleções mais flexíveis.

O que são coleções genéricas?​

Coleções genéricas são classes prontas do .NET usadas para armazenar vários elementos de um tipo específico.

Exemplo:

List<string> nomes = new List<string>();

Aqui estamos criando uma lista que armazena apenas string.

O tipo fica entre < e >:

List<Tipo>

Isso significa:

"esta coleção trabalha com elementos deste tipo".

Se a lista é de string, ela só aceita textos.

Se a lista é de int, ela só aceita números inteiros.

Se a lista é de Revista, ela só aceita objetos do tipo Revista.

List​

A coleção genérica mais comum no C# é a List<T>.

Ela representa uma lista de elementos.

Diferente de um array, uma lista pode crescer conforme novos itens são adicionados.

List<string> nomes = new List<string>();

nomes.Add("Ana");
nomes.Add("Carlos");
nomes.Add("Marina");

O método Add adiciona um novo item no final da lista.

Também podemos criar uma lista já com valores:

List<int> numeros = new List<int> { 10, 20, 30 };

Acessando itens da lista​

Assim como arrays, listas também possuem índices.

O primeiro item continua na posição 0.

List<string> nomes = new List<string>
{
    "Ana",
    "Carlos",
    "Marina"
};

Console.WriteLine(nomes[0]); // Ana
Console.WriteLine(nomes[1]); // Carlos
Console.WriteLine(nomes[2]); // Marina

Isso é útil quando precisamos acessar uma posição específica.

Mas, na maioria dos casos, usamos foreach para percorrer todos os elementos.

Percorrendo uma lista​

O foreach percorre cada item da coleção.

List<string> nomes = new List<string>
{
    "Ana",
    "Carlos",
    "Marina"
};

foreach (string nome in nomes)
{
    Console.WriteLine(nome);
}

Leia esse código assim:

"para cada nome dentro de nomes, execute este bloco".

Esse formato é muito usado quando não precisamos controlar o índice manualmente.

Contando elementos​

Em arrays, usamos Length.

Em listas, usamos Count.

List<string> nomes = new List<string>();

nomes.Add("Ana");
nomes.Add("Carlos");

Console.WriteLine(nomes.Count); // 2

Count informa quantos elementos existem na lista naquele momento.

Como a lista pode crescer ou diminuir, esse valor pode mudar durante a execução do programa.

Removendo elementos​

Podemos remover itens de uma lista com Remove.

List<string> nomes = new List<string>
{
    "Ana",
    "Carlos",
    "Marina"
};

nomes.Remove("Carlos");

Depois da remoção, a lista fica com:

Ana
Marina

Também podemos remover por posição usando RemoveAt:

nomes.RemoveAt(0);

Nesse caso, será removido o item da posição 0.

Atenção: se a posição não existir, o programa lançará uma exceção.

Verificando se um item existe​

Para verificar se uma lista contém determinado valor, usamos Contains.

List<string> nomes = new List<string>
{
    "Ana",
    "Carlos",
    "Marina"
};

bool contemAna = nomes.Contains("Ana");

Console.WriteLine(contemAna); // True

Esse método retorna true quando o item existe na lista.

Caso contrário, retorna false.

Lista de objetos​

Coleções genéricas não servem apenas para tipos simples como int e string.

Também podemos criar listas de objetos.

public class Revista
{
    public string Titulo { get; set; }
    public int NumeroEdicao { get; set; }
}

Agora podemos criar uma lista de revistas:

List<Revista> revistas = new List<Revista>();

Revista revista = new Revista();
revista.Titulo = "Mundo .NET";
revista.NumeroEdicao = 12;

revistas.Add(revista);

Aqui temos uma lista que aceita apenas objetos do tipo Revista.

Isso ajuda o compilador a proteger nosso código.

Não conseguimos adicionar um Aluno, um Produto ou uma string nessa lista.

Dictionary​

Outra coleção muito útil é o Dictionary<TKey, TValue>.

Ele armazena dados em formato de chave e valor.

Dictionary<int, string> alunos = new Dictionary<int, string>();

alunos.Add(1, "Ana");
alunos.Add(2, "Carlos");
alunos.Add(3, "Marina");

Nesse exemplo:

  • a chave é um int;
  • o valor é uma string.

Podemos acessar um valor pela chave:

Console.WriteLine(alunos[2]); // Carlos

Esse tipo de coleção é útil quando queremos localizar rapidamente um item por um identificador.

Por exemplo:

  • buscar um aluno pelo número de matrícula;
  • buscar um produto pelo código;
  • buscar uma revista pelo ID.

Atenção: as chaves de um Dictionary não podem se repetir.

HashSet​

O HashSet<T> é uma coleção que não permite valores repetidos.

HashSet<string> categorias = new HashSet<string>();

categorias.Add("Aventura");
categorias.Add("Tecnologia");
categorias.Add("Aventura");

Mesmo adicionando "Aventura" duas vezes, o HashSet guarda apenas uma ocorrência.

Ele é útil quando queremos representar um conjunto de valores únicos.

Por exemplo:

  • tags de um documento;
  • categorias de produtos;
  • permissões de um usuário.

Queue​

A Queue<T> representa uma fila.

Em uma fila, o primeiro item que entra é o primeiro item que sai.

Queue<string> filaAtendimento = new Queue<string>();

filaAtendimento.Enqueue("Ana");
filaAtendimento.Enqueue("Carlos");
filaAtendimento.Enqueue("Marina");

string proximo = filaAtendimento.Dequeue();

Console.WriteLine(proximo); // Ana

Enqueue adiciona um item no final da fila.

Dequeue remove e retorna o primeiro item da fila.

Esse comportamento é parecido com uma fila de atendimento.

Stack​

A Stack<T> representa uma pilha.

Em uma pilha, o último item que entra é o primeiro item que sai.

Stack<string> historico = new Stack<string>();

historico.Push("Página inicial");
historico.Push("Lista de revistas");
historico.Push("Detalhes da revista");

string paginaAtual = historico.Pop();

Console.WriteLine(paginaAtual); // Detalhes da revista

Push adiciona um item no topo da pilha.

Pop remove e retorna o item do topo.

Esse comportamento é comum em cenários como:

  • histórico de navegação;
  • desfazer uma ação;
  • controle de etapas anteriores.

Comparando as coleções​

Cada coleção resolve um tipo de problema.

ColeçãoQuando usar
List<T>Quando precisamos de uma lista simples e ordenada de itens
Dictionary<TKey, TValue>Quando precisamos buscar valores por uma chave
HashSet<T>Quando não queremos valores repetidos
Queue<T>Quando queremos comportamento de fila
Stack<T>Quando queremos comportamento de pilha

Na prática, List<T> é a coleção mais comum para começar.

As outras aparecem conforme o problema exige uma forma diferente de organização.

Por que essas coleções usam generics?​

Todas essas coleções precisam armazenar elementos.

Mas cada sistema trabalha com tipos diferentes.

Um sistema pode precisar de:

  • List<Aluno>;
  • List<Produto>;
  • Dictionary<int, Revista>;
  • Queue<Pedido>;
  • Stack<Acao>.

Generics permitem que o .NET ofereça uma única estrutura reutilizável para vários tipos.

Ao mesmo tempo, o C# continua verificando se estamos usando os tipos corretos.

Isso traz três benefícios importantes:

  • menos duplicação de código;
  • mais segurança de tipos;
  • código mais claro.

Conclusão​

Coleções genéricas são estruturas prontas do C# para trabalhar com vários elementos de forma organizada.

Elas aproveitam o conceito de generics para manter o código flexível e seguro.

Em resumo:

  • use List<T> para listas comuns;
  • use Dictionary<TKey, TValue> para chave e valor;
  • use HashSet<T> para valores únicos;
  • use Queue<T> para filas;
  • use Stack<T> para pilhas.

Com essas coleções, conseguimos representar melhor os dados do sistema e evitar muitas soluções manuais com arrays.

Esse é um passo importante para escrever programas mais próximos do que encontramos em aplicações reais.
