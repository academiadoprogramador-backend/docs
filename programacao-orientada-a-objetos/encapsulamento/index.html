Encapsulamento

O problema dos atributos públicos​

Nas aulas anteriores, usamos atributos para guardar os dados de um objeto.

Por exemplo:

public class Conta
{
    public string titular;
    public double saldo;
}

Com isso, qualquer parte do programa consegue acessar e alterar esses valores:

Conta conta = new Conta();

conta.titular = "Ana";
conta.saldo = 1000;

Console.WriteLine(conta.saldo);

À primeira vista, isso parece simples.

O problema aparece quando o objeto precisa proteger suas próprias regras.

Nada impede que outro trecho do programa faça isto:

conta.saldo = -500;

Agora temos uma conta com saldo negativo, mesmo que isso não faça sentido para a regra do sistema.

O atributo ficou exposto.

Qualquer pessoa pode alterá-lo diretamente.

O que é encapsulamento?​

Encapsulamento é a ideia de proteger os detalhes internos de uma classe.

A classe continua oferecendo formas de uso para o restante do programa, mas não precisa expor tudo o que existe dentro dela.

Encapsular é controlar como os dados de um objeto podem ser acessados e alterados.

Em vez de permitir que qualquer código altere o saldo diretamente, podemos fazer a própria classe decidir o que é permitido.

Para isso, usamos modificadores de acesso.

Os mais comuns neste momento são:

  • public, quando algo pode ser acessado de fora da classe;
  • private, quando algo só pode ser acessado dentro da própria classe.

Tornando atributos privados​

Podemos começar protegendo os atributos da classe:

public class Conta
{
    private string titular;
    private double saldo;
}

Agora, este código não compila:

Conta conta = new Conta();

conta.saldo = 1000;

O atributo saldo é privado.

Isso significa que apenas a classe Conta pode acessá-lo diretamente.

Mas ainda precisamos de alguma forma de informar e consultar os dados da conta.

É aí que entram as propriedades.

Propriedades em C#​

Uma propriedade é uma forma controlada de expor um valor de uma classe.

Em C#, propriedades normalmente usam get e set.

public class Conta
{
    private string titular;

    public string Titular
    {
        get { return titular; }
        set { titular = value; }
    }
}

O get é executado quando alguém lê a propriedade.

O set é executado quando alguém altera a propriedade.

A palavra value representa o valor que está sendo enviado para a propriedade.

Veja o uso:

Conta conta = new Conta();

conta.Titular = "Ana";

Console.WriteLine(conta.Titular);

Por fora, parece que estamos usando um atributo.

Por dentro, a classe está usando métodos especiais de leitura e escrita.

Propriedades automáticas​

Quando não precisamos de nenhuma regra especial, podemos escrever uma propriedade de forma mais curta:

public class Conta
{
    public string Titular { get; set; }
}

Essa forma é chamada de propriedade automática.

O próprio C# cria internamente o espaço necessário para guardar o valor.

Ela é muito comum em classes simples.

Mesmo assim, ela ainda é uma propriedade, não um atributo público.

Isso é importante porque, se a regra mudar no futuro, podemos transformar essa propriedade em uma propriedade com validação.

Validando valores com propriedades​

Vamos voltar ao exemplo do saldo.

Não queremos permitir que qualquer código coloque um saldo negativo diretamente.

Podemos proteger o campo interno e controlar a alteração pela propriedade:

public class Conta
{
    private double saldo;

    public double Saldo
    {
        get { return saldo; }
        set
        {
            if (value < 0)
                return;

            saldo = value;
        }
    }
}

Agora, se alguém tentar atribuir um valor negativo, a classe simplesmente não aceita:

Conta conta = new Conta();

conta.Saldo = 1000;
conta.Saldo = -500;

Console.WriteLine(conta.Saldo);

O valor impresso continua sendo 1000.

A regra ficou dentro da classe Conta.

Essa é uma das principais vantagens do encapsulamento.

Controlando escrita e leitura​

Também podemos permitir que um valor seja lido por fora, mas alterado apenas pela própria classe.

Para isso, usamos private set:

public class Conta
{
    public double Saldo { get; private set; }

    public void Depositar(double valor)
    {
        if (valor <= 0)
            return;

        Saldo += valor;
    }
}

Agora o saldo pode ser consultado:

Console.WriteLine(conta.Saldo);

Mas não pode ser alterado diretamente:

conta.Saldo = 1000;

Esse código não compila, porque o set é privado.

Quem quiser mudar o saldo precisa usar um método da própria classe:

Conta conta = new Conta();

conta.Depositar(1000);

Console.WriteLine(conta.Saldo);

Assim, a classe consegue garantir suas regras.

Construtores​

Além de proteger alterações, também precisamos pensar na criação do objeto.

Imagine uma conta sem titular:

Conta conta = new Conta();

Dependendo do sistema, isso pode não fazer sentido.

Uma conta pode precisar nascer já com um titular.

Para isso, usamos um construtor.

O construtor é um método especial executado quando usamos new para criar um objeto.

Exemplo:

public class Conta
{
    public string Titular { get; private set; }
    public double Saldo { get; private set; }

    public Conta(string titular)
    {
        Titular = titular;
        Saldo = 0;
    }
}

Agora, para criar uma conta, precisamos informar o titular:

Conta conta = new Conta("Ana");

Console.WriteLine(conta.Titular);
Console.WriteLine(conta.Saldo);

O construtor ajuda a garantir que o objeto comece em um estado válido.

Nesse exemplo:

  • toda conta nasce com titular;
  • toda conta começa com saldo 0;
  • o saldo não pode ser alterado diretamente de fora da classe.

Juntando construtor, propriedades e métodos​

Agora podemos montar uma versão mais organizada da classe Conta.

Observe como os dados ficam protegidos e as operações ficam concentradas na própria classe:

public class Conta
{
    public string Titular { get; private set; }
    public double Saldo { get; private set; }

    public Conta(string titular)
    {
        Titular = titular;
        Saldo = 0;
    }

    public void Depositar(double valor)
    {
        if (valor <= 0)
            return;

        Saldo += valor;
    }

    public bool Sacar(double valor)
    {
        if (valor <= 0)
            return false;

        if (valor > Saldo)
            return false;

        Saldo -= valor;
        return true;
    }
}

E o uso da classe fica assim:

Conta conta = new Conta("Ana");

conta.Depositar(1000);

bool conseguiuSacar = conta.Sacar(200);

Console.WriteLine(conta.Titular);
Console.WriteLine(conta.Saldo);
Console.WriteLine(conseguiuSacar);

Perceba que o programa não precisa saber como o saldo é guardado internamente.

Ele só precisa saber quais operações a Conta oferece.

Por que usar propriedades em vez de atributos?​

Usamos propriedades porque elas deixam a classe mais preparada para crescer.

Com atributos públicos, qualquer parte do sistema pode alterar os dados sem controle.

Com propriedades, a classe pode decidir:

  • se um valor pode ser lido;
  • se um valor pode ser alterado;
  • se a alteração precisa de validação;
  • se a escrita deve ser pública ou privada;
  • se a regra pode mudar sem quebrar o restante do programa.

Por isso, em C#, a prática mais comum é evitar atributos públicos e usar propriedades para expor dados.

Conclusão​

Encapsulamento é um dos conceitos mais importantes da orientação a objetos.

Ele ajuda a manter as regras próximas dos dados que elas protegem.

Propriedades com get e set permitem controlar leitura e escrita.

Construtores permitem criar objetos já em um estado válido.

Quando usamos esses recursos juntos, nossas classes ficam mais organizadas, mais seguras e mais fáceis de alterar.
